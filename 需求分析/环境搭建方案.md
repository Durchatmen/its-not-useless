## 0. 已确认的决策

| 项 | 决策 |
|---|---|
| 前端应用结构 | **两个独立 Vite 应用**：`frontend/`（患者端）、`admin/`（管理/运营后台） |
| 流式输出 | 以技术选型为准，接口文档 `POST /api/v1/ai/multimodal/messages` **已增加 `stream` 参数**（响应为 SSE） |
| Node.js | **v24.21.0** |
| 前端包管理器 | **npm**（Node 自带，不另装 pnpm） |
| Python 包管理 | **pip** |
| 建表方式 | **不写建表 SQL、不用 Alembic**，启动时由 SQLAlchemy 2.0 ORM `create_all` 建表 |
| 大模型服务商 | 不涉及，由项目组自行选型（见 §8） |
| 语音转码 | 不引入 ffmpeg，具体方案随模型选型确定（见 §8） |

### 关于"不需要 MySQL 驱动"

SQLAlchemy 2.0 是 ORM 抽象层，本身不能直接与 MySQL 通信，底层仍需一个 DBAPI 驱动。本方案使用 **PyMySQL**（纯 Python，pip 可直接安装，无需编译）。它不是额外选型，而是 SQLAlchemy 连接 MySQL 的必要依赖，已列入 `requirements.txt`。

### 3.3 `docker/docker-compose.yml`

```yaml

  mysql:
    image: mysql:8.0
    container_name: hospital-mysql
    restart: unless-stopped
    environment:
      MYSQL_ROOT_PASSWORD: root123456

      - ./volumes/mysql:/var/lib/mysql
    healthcheck:
      test: ["CMD", "mysqladmin", "ping", "-h", "127.0.0.1", "-uroot", "-proot123456"]
      interval: 10s
      timeout: 5s
      retries: 12

  # ---------- Redis 7 ----------
  redis:
    image: redis:7
    container_name: hospital-redis
    restart: unless-stopped
    command: ["redis-server", "--appendonly", "yes"]
    ports:
      - "6379:6379"
    volumes:
      - ./volumes/redis:/data
    healthcheck:
      test: ["CMD", "redis-cli", "ping"]
      interval: 10s
      timeout: 5s
      retries: 12

  etcd:
    image: quay.io/coreos/etcd:v3.5.5
    container_name: milvus-etcd
    restart: unless-stopped
    environment:
      - ETCD_AUTO_COMPACTION_MODE=revision

      - ETCD_QUOTA_BACKEND_BYTES=4294967296
      - ETCD_SNAPSHOT_COUNT=50000
    volumes:
      - ./volumes/etcd:/etcd
    command: etcd -advertise-client-urls=http://127.0.0.1:2379 -listen-client-urls http://0.0.0.0:2379 --data-dir /etcd
    healthcheck:
      test: ["CMD", "etcdctl", "endpoint", "health"]
      interval: 30s
      timeout: 20s
      retries: 3

  # ---------- Milvus 依赖 + 业务对象存储：MinIO ----------
  minio:
    image: minio/minio:RELEASE.2023-03-20T20-16-18Z
    container_name: hospital-minio
    restart: unless-stopped
    environment:
      MINIO_ACCESS_KEY: minioadmin
      MINIO_SECRET_KEY: minioadmin
    ports:
      - "9000:9000"     # S3 API
      - "9001:9001"     # 控制台
    volumes:
      - ./volumes/minio:/minio_data
    command: minio server /minio_data --console-address ":9001"
    healthcheck:
      test: ["CMD", "curl", "-f", "http://localhost:9000/minio/health/live"]
      interval: 30s
      timeout: 20s
      retries: 3

  # ---------- Milvus 2.4 standalone ----------
  milvus:
    image: milvusdb/milvus:v2.4.9
    container_name: milvus-standalone
    restart: unless-stopped
    command: ["milvus", "run", "standalone"]
    security_opt:
      - seccomp:unconfined
    environment:
      ETCD_ENDPOINTS: etcd:2379
      MINIO_ADDRESS: minio:9000
    volumes:
      - ./volumes/milvus:/var/lib/milvus
    healthcheck:
      test: ["CMD", "curl", "-f", "http://localhost:9091/healthz"]
      interval: 30s
      start_period: 90s
      timeout: 20s
      retries: 3
    ports:
      - "19530:19530"
      - "9091:9091"
    depends_on:
      - etcd
      - minio

volumes: {}
```

> **要点**
> - Milvus standalone 强依赖 etcd + 对象存储，三者必须一起编排，不能只起 `milvus` 一个容器。
> - 业务文件存储复用这个 MinIO 实例（技术选型给了"本地文件系统 / MinIO"二选一，选 MinIO 可一套存储同时服务 Milvus 与业务文件）。开发阶段也可先用本地文件系统，改一个配置项即可切换。
> - MySQL 只建库，**不执行任何建表 SQL** —— 表由后端 ORM 启动时创建。

### 4.6 建表

**不使用 Alembic，不写建表 SQL。** 在 `app/db/session.py` 建好 `engine`，在 `app/main.py` 的 lifespan 中调用：

```python
from app.db.base import Base
from app.db.session import engine
# 导入所有 models 以完成注册
from app import models  # noqa: F401

@asynccontextmanager
async def lifespan(app: FastAPI):
    Base.metadata.create_all(bind=engine)
    yield
```

ORM 模型需覆盖数据库表设计文档的全部 22 张表，表名统一 `t_` 前缀：

`t_department`、`t_doctor`、`t_user`、`t_patient`、`t_schedule`、`t_appointment`、`t_medication`、`t_prescription`、`t_prescription_item`、`t_bill`、`t_payment`、`t_exam`、`t_exam_report`、`t_medical_record`、`t_ai_session`、`t_ai_message`、`t_medication_reminder`、`t_sms_code`、`t_operation_log`（另有 `t_dept_location` 为可选映射表）。

建表遵循设计文档 1.1 的设计原则：

- 所有表带 `created_at`、`updated_at`
- 业务删除用状态字段软控制，不做物理删除
- 敏感字段（密码、身份证号）加密存储，展示层脱敏
- 与 HIS 交互的数据遵循"本地模拟 + HIS 同步"，按 `external_no` 对账

> `create_all` 只创建缺失的表，不会修改已存在的表结构。开发期若改了模型字段，最省事的做法是 `DROP DATABASE hospital_ai; CREATE DATABASE hospital_ai;` 后重启 —— 这正是移除了 Alembic 之后需要接受的取舍。

### 4.7 关键实现约定（来自接口文档）

| 约定 | 实现位置 |
|---|---|
| 统一响应信封 `code/message/data/timestamp` | `core/response.py` |
| 错误码表 1001~9999 | `core/errors.py` 枚举 |
| **所有主键 ID 序列化为字符串**（防 JS 精度丢失） | Pydantic schema 中 PK 声明为 `str` |
| 分页入参 `pageNum`/`pageSize`，出参 `total/pageNum/pageSize/list` | 通用分页 schema + 工具函数 |
| 时间格式 `yyyy-MM-dd HH:mm:ss`、东八区 | 全局序列化器 + 容器 `TZ=Asia/Shanghai` |
| 金额单位元、两位小数、数字类型 | schema 用 `Decimal`/`float` + 序列化约束 |
| `Authorization: Bearer` | `core/security.py` 依赖注入 |
| Token 失效/无效统一返回 **4002** | 全局异常处理器 |
| 敏感接口（报告/处方/病历）二次鉴权 | 预留校验依赖 |
| 日志留存 ≥ 6 个月 | 日志配置 |

```bash

cd admin
npm install
npm install vue-router@4 pinia axios element-plus ics
npm install -D less postcss autoprefixer
```

两个应用依赖一致，各自独立安装、独立构建、独立部署。

### 5.4 `vite.config.js`（两个应用都要配，端口不同）

患者端：

```js
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'

export default defineConfig({
  plugins: [vue()],
  server: {
    port: 5173,
    proxy: {
      '/api': {
        target: 'http://127.0.0.1:8000',
        changeOrigin: true,
      },
    },
  },
})
```

后台端把 `port` 改成 `5174`。

> SSE（`stream=true` 时响应为 `text/event-stream`）经 Vite 代理转发时不会被缓冲，`/api` 一条代理规则即可覆盖。若前端直连后端而非走代理，需自行处理跨域。

### 5.5 `postcss.config.js`

```js
export default {
  plugins: {
    autoprefixer: {},
  },
}
```

配合 Less 实现技术选型要求的**响应式、大字模式、高对比度**。原型 `index(1).html` 已有一套 CSS 变量（`--primary:#0e9f8f`、`--primary-dark`、`--bg`、`--line` 等），可直接沿用到前端工程。

### 5.8 Axios 实例要点（`src/api/request.js`）

- 请求拦截：注入 `Authorization: Bearer {token}`、`X-Request-Id`（UUID）、`X-Client`
- 响应拦截：解统一信封，取 `data`；`code === 4002` → 清 Token + 跳登录
- 全局错误：按接口文档 2.5 错误码表给出提示文案

### 5.9 SSE 流式调用要点（`src/api/ai.js`）

接口是 `POST`，用原生 `EventSource`（只支持 GET）不够，改用 `fetch` + `ReadableStream` 读取：

- 请求体带 `stream: true`
- 响应 `Content-Type: text/event-stream`
- 按事件类型渲染：`delta` 增量追加到气泡、`triageCard` 渲染分诊卡片与"去挂号"按钮、`sources` 渲染引用来源、`done` 收尾、`error` 兜底提示
- 注意：`stream=true` 时后端返回的不再是统一 JSON 信封，前端要单独处理这条路径

### 5.10 Pinia store 与路由守卫

- `stores/user.js`：登录态、Token、角色
- `stores/patient.js`：就诊人列表与当前就诊人（选型表指定）
- `stores/chat.js`：会话上下文（选型表指定）
- `router/index.js`：全局前置守卫做鉴权与角色分流，角色按需求分析 9.1 的权限矩阵 —— 患者 / 陪诊者 / 医生 / 管理员 / 运营
- 后台端 `admin` 额外按需求分析 9.3 的要求，面向内网 / VPN 访问、独立鉴权

### 5.11 浏览器能力接入

| 6 | 诊疗知识库 | 预诊 |

> 这六类数据**不进 MySQL**（数据库设计文档 4.5）。MySQL 业务表中的 `dept_specialty`、`precautions`、`insurance_type` 等字段只作为知识库条目的结构化引用。
